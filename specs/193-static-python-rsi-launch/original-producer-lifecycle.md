# Original fixed-producer lifecycle continuation

Status: default-off source/composer, private native v4 channel, bounded host
capture, broker exchange retention and original-run computation join implemented;
consolidated regression completed with the first failures retained and the affected
355-case successor passing. Actual generic-envelope delivery remains unwired. The finite Linux pycache monitor is diagnostic
only: original native writable-capability enclosure and writer quiescence are
not connected. Actual native solver execution and accepted build/runtime roots
remain unaccepted. This adds the next acquisition boundary to the
existing Feature 193 startup and native evidence inspection work. It does not
reinterpret a completed startup inspection as a completed solver lifecycle.
Implementation remains within the existing P0–P2 scope and retains its current
acceptance boundaries.

## Current software slice and open acceptance

The lifecycle profile retains actual request/reply bytes only inside the host
broker's private original acquisition, after its sole completed response has
been fully written. Its durable budget journal and public observation do not
contain those bytes. Copies, reconstruction and recovery cannot restore this
process-local acquisition. The native owner retains the original completion
reader, input descriptor, PID, sealed execution image identity, original
deadline, committed artifacts and broker acquisition separately from the public
diagnostic bytes. Source executable identity and sealed execution image identity
are distinct and must each satisfy their own checks.

Only the complete original chain and the original captured envelope's material
semantics can verify the computation observation. A missing leg keeps the
boundary missing; a changed leg refuses comparison. The inspection continues to
report `incomplete` and all admission/runtime/publication authorities stay false.
The pure wire comparer remains non-authoritative even on matching bytes.

`static_python_pycache_monitor.py` provides an explicitly selected Linux
diagnostic capture for a finite list of existing directories. It installs all
watches before the initial scan, binds directory identities, retains bounded
kernel events and marks topology changes, watch loss, overflow, cache events
and deadline loss. It does not authenticate the caller's grants manifest or
enclose all native writable capabilities. Finishing releases the monitor and
records `original_quiescence_unavailable`; target exit, empty queues and public
booleans cannot complete coverage. This software must not clear
`original_pycache_observation`. A supported-kernel test is distinct from a pure
parser test, and neither substitutes for the missing original native join.

The focused suite includes legacy compatibility, actual local file/pipe and
inotify fixtures, pure comparisons and controlled provenance fixtures. The 53-file first run retained 20 failures and one Darwin-only skip; the
12-file affected successor passed 355 cases and Darwin separately passed its
one actual platform node. These are source-bound, overlapping runs, not an
aggregate of repeated passing cases. Until subsequent actual acceptance finishes, the implementation
must not be described as a completed actual static producer lifecycle.

## Existing behavior and required separation

The expanded fixed runtime currently observes startup facts from the executing
interpreter. Both fixed producer entrypoints then read the original request and
memory grants, perform one brokered proposal, validate/apply a constrained diff,
and commit their external artifacts. They generate candidate programs; they do
not execute or evaluate those programs. An observation of that proposal and
artifact computation must never be described as a candidate correctness result.

The original startup writer is FD 198. `launcher_live_sink.c` closes it before
importing/calling the solver. `NativeFixedLiveSinkCapture.finish()` synchronously
reads to EOF before the host resumes the producer/broker flow. Reusing this pipe
for post-solver records would remove the EOF that permits that flow to continue.
It is prohibited to retain FD 198 until completion or to append a solver result
to its existing startup wire.

Use a separately versioned, explicitly selected, default-off completion profile
and a distinct original-attempt private channel. Legacy launcher bytes, startup
pipe semantics, profiles and native CLI refusal remain unchanged. Selecting the
new profile changes the source closure and requires a rebuilt, independently
pinned image; an old image cannot be reauthenticated by changing metadata.

## Original computation acquisition

The minimum successor records bounded facts produced by the actual frozen
entrypoint, with two ordered phases: begun and committed. The versioned wire
must fix its exact fields, record count, byte limits, canonical encoding and
refusal codes before implementation. It exports digests and sizes, not raw
request/memory, broker credentials, replies, prompts or arbitrary paths.

The original chain is:

1. The trusted native owner creates and binds the completion reader/writer to
   this original launch, target image, PID, manifest/marker and absolute
   monotonic deadline. The target receives only its writer. The host starts
   bounded reading concurrently with native-owner and broker progress, before
   allowing target execution; it never waits for solver completion while
   preventing broker progress.
2. The executing entrypoint records its begun phase before proposal work. After
   the existing bounded `_read_at` operations, it records the actual immutable
   request and memory bytes' sizes/digests and validates their existing DTOs.
   It does not reread host-selected paths to manufacture equivalent inputs.
3. At the sole `req-1` exchange, the fixed code retains sizes/digests of the
   actual body, status and reply consumed by this invocation. These local facts
   are compared with the original host broker transcript and request count;
   the target is not the authority for broker completion or budgets.
4. The fixed computation retains sizes/digests of the actual candidate and
   wrapper/SQLite bytes it calculated. OpenEvolve commits `candidate.py` and
   then `result.json`; Shinka commits `gen_0/main.py` and then
   `programs.sqlite`. The committed phase is emitted only after all required
   writes and directory fsyncs return successfully, including the final commit
   artifact. An earlier candidate file is not completion.
5. A versioned frozen wrapper/launcher captures the actual return facts of this
   one `_rsi_launch` call. The original completion channel carries those facts
   under the original deadline. A solver exception or unsuccessful commit
   cannot emit a committed success record. The host preserves actual native
   terminal and cleanup outcomes separately from target-reported phases.
6. After the original native terminal, the existing original-run handoff joins
   the retained channel bytes with the same `NativeTrustedProducerRun`, startup
   observation, launch intent/attestation, broker transcript, input grants and
   original privately acquired captured envelope. Committed artifact bytes
   must agree with the bounded prepared envelope and corresponding external
   source snapshots. The final validation rechecks original object identities,
   helper/source fingerprints and material drift.

The completion reader must be integrated into the original attempt's concurrent
event loop or a bounded owned reader whose lifetime and cancellation are joined
by that owner. It must not introduce a second scheduler, launch, broker request,
implicit retry or ownership registry. Every read/write/wait consumes the
original absolute deadline. A child-local stricter cap is allowed; success may
not renew the parent deadline or turn a wall-clock value into a fresh allowance.

Only an acquisition retained by this original attempt can satisfy
`original_computation_observation`. A public DTO, reconstructed canonical JSON,
same-value copied container, supplied digest or host-generated completion file
cannot supply it. Any detached inspection form remains non-authoritative. This
observation alone never enables adapter admission, production CLI or publication.

## Unknown and failure states

No committed observation is available when the original channel is absent,
truncated, oversized, duplicated, reordered, noncanonical or detached from the
original launch. The same applies to missing input/broker/output agreement,
replaced objects, changed source fingerprints, an expired original deadline,
cancelled acquisition, target exception, native terminal disagreement or
unconfirmed cleanup. Preserve bounded partial records and the original refusal
or timeout; do not retry into a successful acquisition or replace an original
failure with reconstructed evidence.

A begun record, committed record and clean EOF are distinct facts. Even a valid
committed record cannot prove process quiescence or override an unknown native
terminal/cleanup result. Inspection reports retain `incomplete` and their
existing false authority claims whenever an independent required boundary is
missing.

## Pycache acquisition: snapshots and full lifecycle

The current kernel policy allows file and directory creation/removal within
write grants. A target could create and remove a bytecode cache between two
directory scans. `dont_write_bytecode`, startup module facts, `__cached__`, an
initial/final scan and a Python/C audit hook alone do not observe every native
filesystem syscall. None may clear `original_pycache_observation`.

A first implementation may export explicitly named before/after snapshots and
runtime flags as diagnostic facts. Its coverage must say `snapshots`, with the
original full-lifecycle missing boundary retained. It must not export an
unqualified `pycache_absent=true` or silently feed the legacy nine-module DTO.

A later strict full-lifecycle profile must establish a complete, fixed write
view before claiming absence. Its minimum contract is:

- Identify and bind every original writable directory and inherited writable
  filesystem handle, including working, output and temporary locations. Pipes
  and host capture streams must be accounted for separately. An unmonitored
  write capability refuses this profile; read-only imports do not expand it.
- Prepare the finite allowed directory layout before target start, bind its
  actual identities to original grants, and install independent native kernel
  monitoring before the target can execute or initialize Python. For Shinka,
  any precreated `gen_0` layout and its existing-directory behavior belong only
  to the new versioned profile; legacy `mkdir` behavior stays unchanged.
- Establish the initial cache-free view without a monitoring gap, then retain
  bounded original kernel events throughout execution. All allowed writable
  directories must already be monitored. Directory creation or relocation,
  replaced roots, mount/watch loss, unaccounted aliases or handles, event queue
  overflow, malformed/truncated event data or deadline loss makes coverage
  unknown and refuses absence. Adding watches after target-created directories
  appear does not repair an earlier coverage gap.
- Define the finite artifact naming policy explicitly: standard `__pycache__`
  path components, `.pyc`/`.pyo` bytecode-cache artifacts and their standard
  temporary filename forms, including transient creation or moves into
  monitored directories. The claim concerns that
  declared artifact policy, not arbitrary semantic interpretations of file
  content or all possible application caches.
- Continue monitoring until the original native owner confirms terminal state
  and process/descendant quiescence, then drain the original event stream. A
  target-level return or completion-channel EOF alone cannot end coverage.
  Preserve any observed cache event as a negative result. Unconfirmed
  quiescence or incomplete events remain unknown, even if final scans are clean.

Linux inotify is a candidate implementation for this stricter finite directory
profile, not an already accepted proof. Its actual syscall/event coverage,
grant identity binding, initial-scan ordering and post-terminal drain must be
tested before the profile can remove the missing boundary. Unsupported kernels
or hosts must refuse actual lifecycle acquisition. Portable mock tests may run
locally, but their success cannot substitute for a supported kernel execution.

## Independent authority prerequisites

`accepted_build_input_custody` and `accepted_runtime_authority_root` remain
independent acceptance/environment prerequisites. Neither real completion
facts nor kernel monitoring grants those authorities. Complete controlled
build inputs, immutable custody, the accepted runtime construction and their
independent evidence must exist separately. Installing build tools or obtaining
KVM access alone is not acceptance. No host-Python, dynamic interpreter,
detached descriptor, alternate image or accepted-runtime fallback is permitted.

## Remaining original output delivery gap

The current fixed producer writes its own candidate and wrapper/SQLite artifacts,
but does not write the generic `intent.envelope_path` consumed by the native
capture path. The original-completion positive fixture supplies that envelope
through an explicitly inert seam. Its passing result tests private-acquisition
and material semantics; it does not establish actual fixed-producer delivery.
The successor must bind a separately versioned original launch descriptor before
the target generates and commits the generic envelope. A host-created envelope
assembled from matching hashes cannot repair this missing original computation.
