# Expanded startup and original native evidence inspection

Status: all 45 synthetic focused cases passed in the shared Linux regression
of tree `7628e971` (758/759 for the full batch; an unrelated host mock failed).
This is an
explicit read-only inspection/export seam, not a completed expanded adapter,
admission gate, accepted runtime root or production CLI.

`static_python_fixed_producer_evidence.py` consumes the original
`NativeTrustedProducerRun`, original `FixedPythonLiveSinkRequest` and original
launch intent/attestation. The expanded startup observation is compared again
against the retained image, composed source and independently parsed installation.
The existing native evidence helper also reparses the complete formal receipt
and retains the current-call attempt, receipt, prepared output and sink snapshot.

The new join compares launch/run/journal/parent/task, executable digest/size and
device/inode, observed PID, attestation, registration, native terminal and stream/
output capture digests. It checks the retained broker identity, original absolute
monotonic deadline, journal digest/size/file identity, request counts and limits,
complete broker status, result identity/material envelope and admission-plan
context. These are consistency comparisons of supplied original objects, not
independent proof that an untrusted caller acquired them correctly.

The retained container holds strong references to itself and the original
objects. Same-value container, run, intent, request, nested native result or raw
snapshot replacement is refused on subsequent inspection. The original sink
request pin and a finite actual helper identity/code/default/capture fingerprint
are rechecked. Every export recomputes the join; exported JSON is never accepted
as a replacement for original objects or as execution authority.

There is no original captured-envelope wire in this API. Equality of the supplied
envelope-file digest across receipt/output does not prove that the supplied
generic envelope DTO was parsed from those captured bytes. That semantic join
therefore remains an explicit missing boundary, even when a local source snapshot
matches the supplied envelope DTO. The report is supplied-original-object
relationship inspection, not verification of native acquisition or an adapter.

The bounded canonical report has the distinct protocol
`lunar-fixed-python-producer-evidence-inspection-v1`, a self-digest, the original
startup wire and the joined digest projections. Its status is `incomplete`.
`live_runtime_authenticated`, `immutable_custody_verified`,
`production_admission` and `online_publication` are false. The attestation nonce,
broker credentials, process output and arbitrary native paths are not exported.

The explicit source export reader compares local OpenEvolve result/source or
Shinka SQLite/source snapshots against the retained generic result envelope.
It rechecks original evidence before source I/O and after the source read, makes
no writes, runs no evaluator and cannot publish candidates. External scores are
digest-bound provenance only. A matching source snapshot leaves the report
incomplete.

Five missing boundaries are exported explicitly:

- An original computation observation tied to this executing solver.
- An original pycache-absence observation covering the required lifecycle.
- An original captured-envelope wire and its verified semantic envelope join.
- Independently accepted build input custody for the complete configured build.
- An accepted runtime authority root and its original lifecycle construction.

The repository currently has no production acquisition mechanism for the first
two facts. A caller-supplied digest or `pycache_absent=True` cannot fill them;
the old nine-module fixture observation is not converted to an expanded one.
Adding a new completed-runtime successor requires actual collection and its
source/image/lifecycle binding before changing adapter/export/admission policy.
The legacy adapter, export, admission gate and native CLI refusal remain intact.

The new focused tests use synthetic native records and an inert ELF description,
plus ordinary local source snapshots. They cover original joins, all explicit
missing/false fields, same-value replacements, native linkage drift, helper/class
descriptor drift and material export drift. No actual CPython build, solver,
model, remote evaluator or production runtime acceptance is implied.
