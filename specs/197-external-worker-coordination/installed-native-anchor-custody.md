# Installed native bridge and independent restart-anchor custody

Status: narrow software continuation. Production runtime/account acceptance and
abnormal guardian cleanup remain unaccepted. Central focused/static regression
is run by the batch owner after this slice freezes.

## Contract

An explicit trusted installation caller supplies the original held private vault
directory chain, installed worker/host/boot/key identity and profile digest. This
creates an immutable, private installation reference, retained independently of
worker episode files. No worker channel, current packet, filesystem scan or
environment variable can select or manufacture that reference. Its original
chain pins are compared on each use; the vault leaf belongs to the installed
caller and is 0700. Ancestors are root/caller owned and not group/other writable,
except a root-owned sticky temporary ancestor used by local fixtures. This is a
trusted local filesystem installation, not immutable or remotely attested custody.

The opt-in wrapper receives an exact trusted native bridge object. Defaults and
channel-v1 stay unchanged. The bridge contains a previously authorized original
intent/attestation/artifact, complete request and explicit six-ID mapping; it
does not issue an attestation or derive authorization from a wire request. There
is no implicit factory, production-ready boolean, host-interpreter fallback or
public native-launch command. An absent bridge refuses the explicit installed
entry point. Deployments must independently establish the installed runtime and
candidate/account isolation before supplying an untrusted candidate.

For a new original worker intent, the wrapper retains its actual publication-FD
pin and a separate held episode chain. The bridge calls the existing real native
runner with the existing resolver/writer inside its registered observer. After
packet/completion publication, that observer exclusively writes the original
anchor, lookup and original expected context/mapping to the separate vault. It
uses a distinct HMAC domain and compares installed identity/profile/key and
original directory chains before/after durable file/directory publication. The
vault and episode/native stores cannot be the same or nested directories.
Only then may the observer return. Writer, vault, recheck or fsync failure
propagates to the original native gate; no retry, repair or deadline renewal occurs.
The existing native runner rechecks context/deadline after the callback.

The wrapper retains unknown after this process-only path; it does not seal a
solver receipt from native exit zero. The explicit worker-local installed
restart API takes the independently retained installation, key and original
expected context/mapping/profile. Its public lookup contains no paths or native
capabilities. It loads only that fixed lookup's create-only trusted vault entry,
validates its authentication and exact originals, then calls the existing
`inspect_native_restart`. It never prepares an observer, consumes a nonce,
launches, signals, repairs files or refreshes deadlines. Reads recheck installation,
key, held chains and vault entry bytes/identity after native observation. Missing,
partial, drifted, duplicate or unconfigured state stays unavailable/unknown.

The vault payload preserves the original packet/completion creator pins. Current
metadata of the vault entry is only a stability comparison during that trusted
read; it is never used to create a missing original native anchor. The trusted
installation and caller's private filesystem protect the independently stored
anchor across processes. This does not claim protection from a compromised
installed signing account or root. Every diagnostic keeps native success,
publication, remote-cleanup and production authority false.
