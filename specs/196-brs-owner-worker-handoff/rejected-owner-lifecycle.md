## Observable behavior and authority

One original selected worker, original publication mailbox and original admission
channel remain bound to the same original owner. A genuine native `all_rejected`
transaction is a known failed solver outcome. It does not publish a candidate,
advance population or memory, or acquire a fresh attempt. The worker can complete
only after the owner retains C1, writer-returned provenance P and C2, validates the
existing admission and supplies the exact staged ACK and exact mailbox result.
The owner then accepts the actual terminal episode/claim/result, saves one root
`executions` entry with exact readback and retires its old authority once.

Keep `handoff.ordinal == 0`, original `M0`, full-wave reservation, original deadline,
all existing capacity ceilings and public refusal gates. Serial append lineage and
fresh sibling dispatch remain the next behavior continuation. Do not reconstruct
DRS authority, a lineage owner or a launch from completed evidence.

## Continuous order

1. Freeze the original selected intent/handoff, original native context and run
   lease. The normal runner naturally creates its running episode/started claim.
2. The worker submits its detached original preparation request to the one-shot
   mailbox and waits. This transport is distinct from admission ready/ACK.
3. The owner registers the existing durable recovery fence, invokes the existing
   shared native transaction and retains the genuine before/prepared evidence.
4. On actual `all_rejected`, the private exact-owner dispatch selects
   `retain_rejected_terminal(terminal)`, then calls
   `retain_rejection_provenance()` and `retain_rejection_ready_capture()` once.
   The original empty-channel checks remain strict. No ACK has been exposed.
5. The original terminal lifecycle passes only the pre-arm capture's existing
   canonical `native_plan/prepared_journal/expected_anchor_sha256` bytes to its
   original worker endpoint. These comparison bytes confer no authority. It
   calls the existing `service_rejection_ready(timeout=...)` once.
6. While the same worker waits for the final mailbox response, its original
   wait-check observes the original channel's armed worker guard, submits that
   exact prepared payload through the existing `BRSAdmissionChannel.request`,
   and receives the actual original ACK. It never submits before arming. This
   bounded intermediate exchange prevents a mailbox/ready circular wait; it is
   not a second worker, mailbox response, permit registry or arbitrary handler.
7. Only after ACK commit may the owner generate/deliver the existing exact
   `all_rejected` result envelope. The worker receives it through the original
   endpoint, invokes its settlement callback once, and naturally persists the
   failed terminal native result and episode. No success manifest is fabricated.
8. The original lifecycle records delivery/callback/worker-terminal facts with
   rejection journal and original C2/P lineage. Close precedes executor join.
9. Exact original result acceptance and root checkpoint readback produce one
   selected execution entry. Only then retire the old owner/handoff. Explicit
   fresh terminal evidence may finish a provable interrupted root settlement;
   removing a recovery fence alone is not root settlement or launch authority.

The root transaction adds that selected `executions` entry and removes its exact
reconcile obligation atomically under captured source pins. The public
`reconcile_brs_terminal` acquires the nonreentrant run lease once, then calls the
exact private `_reconcile_brs_terminal_locked` implementation. An original live
owner already holds that lease and invokes the same private implementation
directly. The helper asserts the original lease before observation; it does not
release it or make controller locks reentrant. The result remains the existing
`observation`/`consumption` mapping.

## Private interfaces

- `_run_original_brs_native_publication(owner, request, original_preparation=...)`
  retains its existing signature. Published behavior stays compatible. A genuine
  rejected result returns only after original C1/P/C2 and pre-arm capture; it
  does not itself wait for ready, settle the worker or clear the fence.
- `_call_original_brs_owner(..., "retain_terminal", terminal, None)` selects only
  the exact original `retain_rejected_terminal`. No duck-typed owner, worker
  callable or new method selector is admitted.
- `BRSOwnerTerminalLifecycle._service_rejection_admission(timeout=...)` uses only
  its already-held owner/mailbox/channel/worker endpoint and original capture.
  It publishes the bounded comparison bytes and calls the original dedicated
  service. It neither constructs a pending/ready nor supplies a commit callback.
- `run_brs_owner_publication_mailbox(..., _terminal_lifecycle=...)` may accept the
  exact original lifecycle as a private composition argument. Rejection requires
  that same owner/mailbox session; success keeps its existing path. There is no
  fallback to legacy service or caller handler if the lifecycle is absent.
- Worker endpoint wait-check consumes at most one offered prepared payload and
  calls the existing original channel request. Callback failure, changed payload,
  thread/channel drift or duplicate attempt poisons the exchange. No owner,
  ledger, strategy or publication capability is passed to the worker.

## Failure and recovery

Missing/unknown native terminal, source/runtime/material/head drift, cancelled or
expired control, incomplete C1/P/C2, early ready, failed ACK, response/callback
uncertainty or root CAS/readback uncertainty preserves all actual durable evidence
and old captures. Do not refresh, rearm, clear assigned ACK fields, retry a
transaction/callback, adopt latest head, launch another episode, or promote unknown
to known rejection. Already delivered response is not proof of callback success.

Fresh read-only recovery uses the existing independent process, mailbox, terminal,
claim/result and original material evidence. Root settlement must remain bound to
the captured selected request, frozen M0/reservation and exact terminal result.
Retirement follows verified root settlement, never just worker join or fence
removal. No old owner is recreated during resume.
