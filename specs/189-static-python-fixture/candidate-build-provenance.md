# Candidate build source and fixed-patch provenance (P1 design)

Status: design only. This slice defines the evidence boundary for retaining the
complete CPython candidate source tree and exact fixed patch set for a future
configured build. It adds no API, wire schema, builder, or build permission. No
configured build currently consumes a source tree whose complete staging record
and provenance package are independently retained.

## Existing evidence and the open gap

The existing components provide separate, deliberately limited observations:

- `source_tree_observation` records the complete original regular-file inventory
  from one archive snapshot under an externally supplied source-tree pin.
- `source_staging` stages that source and applies the fixed five-file patch
  policy, retaining a canonical staging manifest.
- `candidate_build_source` joins canonical staging, patch-policy, and source
  profile records under independently supplied digest arguments. Its
  `source-only` receipt compares detached bytes and cannot establish who
  produced them or whether a build used them.
- `candidate_build_source_observation` reads and hashes the staged filesystem,
  matches every fixed-patch preimage/postimage, reconstructs the original source
  tree, and emits a `staged-source-observed` record. Its sequential read-only
  walk is not an atomic snapshot and does not prove later build consumption.

The real-source observer replay described in
[`candidate-build-source-receipt.md`](candidate-build-source-receipt.md) used
the correct original source-tree and fixed-patch pins, but its staging-manifest
digest was generated by the same staging run. Its full evidence remains on a
remote disposable host, and signature verification was not repeated in that
observation. It is an observer exercise, not independently retained candidate
build provenance.

The configured-build prerequisite is also open. The retained configure attempt
failed before producing a Makefile, and its source directory was modified. The
current driver refuses configure/build/freezer execution. The observed stock
static build and startup failure are distinct historical probes; neither
consumed the reviewed finite candidate under a frozen recipe. Therefore this
slice must not mint a build-consumption receipt or describe any prior build as
using the fixed patched source tree.

## Contract for a future retained evidence package

The package is assembled only after a clean source staging result exists and
before any claim that a build consumed it. The operator or reviewer retaining
the package supplies pins outside the process that created each corresponding
record. A record may not serve as its own external pin.

Retain these canonical bytes, their byte counts, SHA-256 digests, custody
location, and the independent verifier's result together:

1. The verified source archive receipt and its independently retained archive
   bytes or controlled archive reference, including signature-verification
   status. A source-tree hash or Git object ID does not replace the archive
   identity or signature record.
2. The complete original source-tree observation and its canonical tree bytes,
   bound to the independently retained original source-tree digest.
3. The complete staging manifest and the staged-tree observation record from
   `observe_staged_candidate_source_tree`, each preserved byte-for-byte. The
   staging-manifest digest must be checked and retained by an independent
   custodian; a digest copied only from the staging producer's output is not an
   independent pin.
4. The exact canonical fixed patch policy returned by the reviewed
   `source_patch_manifest()`, not just a list of paths or a policy label. Retain
   both the policy digest and `patch_set_sha256`, which binds the canonical
   `files` vector. For each fixed file, preserve path, preimage and postimage
   size/hash, and every fixed operation's label, before/after size/hash, and
   required occurrence count.
5. The existing candidate-build-source receipt and digest, composed only after
   checking the separate pins above. It is labeled `source-only`; it remains a
   consistency receipt rather than an observation of build use.

The independent comparison must establish all of the following before the
package can be called a retained staged-source record:

- the original source-tree digest covers the complete sorted archive regular
  file inventory, with its digest domain kept distinct from the Git tree,
  compressed archive, staging manifest, and staged-tree projection;
- the staging manifest has a complete, duplicate-free path inventory and its
  externally retained digest matches the exact canonical bytes;
- every unpatched file has equal original and staged size/hash, and every fixed
  patch file has the exact pinned source preimage and staged postimage;
- the policy digest and patch-set digest match the reviewed fixed policy. The
  archive receipt and original source-tree DTO carry the source version, while
  the patch policy, source profile, and source-only receipt directly carry both
  source version and commit. Staging and observer DTOs do not all repeat those
  identifiers; verify their transitive binding through the independently pinned
  archive, root, source-tree, staging, policy, and patch digests instead of
  claiming every DTO directly contains version and commit;
- the staged filesystem was read through the existing no-follow observer and
  matched the complete staging inventory during that observation; and
- all raw records and verifier notes are copied to durable independent custody,
  then their copy hashes are checked after transfer.

An absent, drifted, noncanonical, partial, or independently unpinned record
refuses the retained-provenance claim. Preserve the original failure and any
partial staging evidence; do not reconstruct a successful record from the
resulting directory or replace an earlier failure with a later probe.

## Build-consumption boundary

The package above proves, at most, that a particular staged tree was observed
to match a particular original source tree and exact fixed patch policy at one
time. It does not prove a configured build consumed the observed bytes. The
existing staged-tree observer is sequential, so checking it immediately before
configuration is insufficient if the tree can change before or during later
reads.

Before introducing a build-consumption record, the implementation design must
select and demonstrate a source-custody mechanism that keeps the exact staged
tree immutable for the complete configure, generation, freezer, compile, and
link interval. The mechanism must be enforced by the environment under which
the build runs; chmod, a before/after hash alone, a path string, or an observer
record is not evidence of immutability. The build must use a separate output
directory so generation does not mutate the retained source tree. If the
selected build path cannot guarantee this, it must refuse to advance the
source-consumption claim.

A later consumer record may be designed only after the configured recipe and
toolchain are frozen. At minimum, its independent pins must bind the exact
staged-tree observation and patch-policy bytes above to the build-run record,
the actual source root opened by the build driver, the complete configured
source-input disposition, toolchain/recipe/environment pins, and the build
result bytes. It must keep source provenance separate from generated headers,
toolchain files, compiler support, system libraries, and output artifacts. The
record may say `build-source-consumption-observed` only if the selected
immutability and input-binding mechanism is exercised and independently
verified. A matching receipt digest or a successful compile alone is not
sufficient.

No consumer-record field names or wire version are frozen by this design. The
actual configure/build interface, source-custody mechanism, and source-input
closure do not yet exist as trusted evidence. Freezing a new wire before these
choices are resolved would encode assumptions as facts.

## Evidence obligations before implementation or acceptance

Keep the following items open until their evidence exists:

- independently retain and verify the archive, detached-signature result,
  original complete source-tree DTO, clean staging manifest, staged-tree
  observation, exact fixed patch policy, and source-only candidate receipt;
- preserve the staging-manifest digest outside the staging producer and
  independently verify the complete retained package after transfer;
- retain a new clean staged tree from those bound inputs; do not use the
  configure-mutated diagnostic directory;
- finish an independently pinned compiler/sysroot/libc profile and frozen
  configure/build/freezer recipe, including all actual environment, helper,
  cache, and generated-input dispositions;
- implement and independently exercise an enforced immutable source-custody
  boundary for the whole build interval, with build outputs kept separately;
- bind the actual configured build's source inputs to that custody boundary and
  retain successful and failed build records, including the first failure;
- independently audit the raw evidence package, transfer hashes, module/source
  provenance, final source revision/tree, and any build-consumer record; and
- pass exact-source CI and required Linux acceptance gates before any
  Feature189 merge or runtime/admission claim.

Until these obligations are complete, `build_performed` remains false in the
existing source receipts, `candidate_build_consumption_observed` remains false
in staged-source observer records, and G1 candidate-build provenance plus G2
configured-build closure remain open. This P1 design does not enable configure,
build, freezing, solver execution, or evaluator/network activity.
