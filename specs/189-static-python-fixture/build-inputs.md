# Offline build-input preparation contract

This slice continues Feature189 G1/G2 with one fixed reviewed source/object
candidate and separate freezer/target input plans. It performs no acquisition,
configure, compilation, freezing, linking or target execution. The Linux driver
exits 78 before configure/make/freezer commands even when execution is explicitly
requested: the unresolved configured closure is not admitted to execution.
All runtime/protection/production claims remain false.

## Pure API and fixed reviewed input

`emit_static_python_build_inputs(reviewed_inputs: bytes)` in
`tools/static_python_fixture/build_inputs.py` returns a fresh built-in dict.
Accept only exact built-in bytes, at most 128 KiB, with the fixed complete
reviewed-input SHA-256 and canonical JSON for schema
`lunar-static-python-reviewed-build-inputs-v1`. The reviewed input is the inert
`tools/static_python_fixture/reviewed-build-inputs.json` asset. The API does not
open this file, discover sources or accept caller-selected vectors.
Its fixed encoding is sorted keys, two-space indentation and exactly one final
LF. This is separate from the compact archive-receipt wire encoding.

The output uses schema `lunar-static-python-build-inputs-v1` and records the
reviewed-input size/digest; source version/commit/profile and reviewed control
pins; shared/freezer/target units; freeze tasks, generated sources and fixed
source-preparation policy; stock exclusions, unresolved configuration, required
later checks, compile/getbuildinfo requirements, the fixed installation profile
header and unobserved states. A fresh
mutable plan dict is not a capability or execution receipt. Hashing or matching
the fixed JSON does not prove that any real build input was acquired or used.

## Separate freezer and target plans

Keep shared candidates, builtin additions and stage-specific entries explicit.
Do not present a concatenated vector as one executable used for both stages.

The freezer stage adds reviewed `Programs/_freeze_module.c` and
`Modules/getpath_noop.c` to the shared candidate. The C freezer defines and
initializes deliberately empty bootstrap/stdlib/test/custom frozen tables and
aliases, with importlib and main initialization disabled. It must not link
the target's finite `Python/frozen.c`, stock `Python/frozen.o`, stock getpath
or `_bootstrap_python`. This avoids depending on or importing the headers
that the freezer is supposed to produce. No host interpreter or stock
regeneration script is a replacement for the same-source C freezer.

The target stage adds the installation-owned launcher, initialization profile,
strict getpath and finite frozen-table sources. Exclude stock
`Modules/getpath.o`, `Python/frozen.o`, `Programs/python.o` and
`Programs/_bootstrap_python.o`; do not accidentally retain both implementations
or generate duplicate table/global definitions. These exclusions describe the
planned input vector. They are not an observed link/symbol audit.

dependency requires an explicit reviewed candidate revision; it is not
automatically admitted after a compiler or startup failure.
