# Reserved-history owner-operation pure comparison

## Boundary

The retained mixed timeout stacks repeatedly enter the reserved history walker.
Its checkpoint SELECTs, complete ledger/prefix observations, retained materials,
claim checks and settled rejection provenance remain live. Stack membership is
evidence of repeated paths, not CPU percentages or a performance acceptance.

Only the deterministic historical wire comparisons may be shared inside the
existing controller full-gate operation. The original shape method is not pure:
missing-archive source validation observes the current evolution directory's
inode. Every historical non-rejected entry therefore repeats that physical
shape call even on a pure-comparison hit. Misses preserve its original position
between comparisons; settled terminal/rejection material checks stay after it.
The skipped rejected-entry comparison parses the provenance reference and
`NativeRSIRejectionFilePin` only; it does not read the referenced file. Its
prepared/rejected journal arguments are exact dictionaries, so their parsers
take the in-memory mapping branch. The independent settled provenance reader
and all retained-file observations remain outside the reusable comparison.

## Identity, key and lifetime

Use one thread-local scope bound to the exact wave, handoff and original private
owner object. Nested operations share it; another owner or thread uses the
original path. Exit, error and cancellation discard retained comparisons. No
scope spans a whole wave or generic mailbox service tick.

Each key contains the freshly observed policy digest, complete association
bytes, exact ordinal, ordered complete historical lineage wires with field
presence, every prefix's domain/canonical/batch bytes, and complete expected
current lineage wire. Retain only immutable bytes/scalars/tuples and accounting
markers, never a successful live-validation result, returned DTO or file pin
authority. Bound retention to eight entries and sixteen MiB of conservative
units. Invalid/oversized optional encodings retain the original refusal path.

Check the original complete finite executable policy graph and complete key
before reuse and after shape observations. Strong closure capture references
use identity comparisons and cannot be replaced by numeric object IDs. Graph,
helper, input or policy drift disables reuse; errors clear the cache. Complete
canonical keys and full graph checks have a cost, so performance remains an
open acceptance item until the joined regression and mixed attempt finish.

## Validation

The focused projection tests profile original C1/C2 calls without replacing
them; a hot comparison must skip those pure calls and still invoke every
original shape check. Cover canonical-equivalent fresh DTOs, all complete key
axes, current-wire refusal, helper/code/capture drift, nested owner/thread
isolation, later-operation freshness, cancellation and bounded retention.
A real local missing-archive case replaces the evolution directory inode and
must still refuse on a cache hit. These fixtures confer no producer or native
runtime authority. Existing reserved owner/policy/rejection/capacity and joined
controller tests remain required; tests are dispatched once by the integration
owner after the parallel implementation freeze.
